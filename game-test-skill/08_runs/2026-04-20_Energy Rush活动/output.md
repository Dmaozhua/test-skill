# 测试分析输出：Energy Rush——充能狂潮活动

---

## 1. 需求摘要

- 功能名称：Energy Rush（充能狂潮）——付费体力售卖活动
- 功能目标：以不放回抽取 + 递增价格的付费模型，售卖体力并搭配卡包，刺激玩家付费
- 玩家入口：主界面右侧活动入口列表 → 弹出活动主界面；登录弹窗；体力不足弹窗
- 归属专项：**活动 + 热更 + 弱网专项**（主）；订单-奖励-剧情闭环专项（次级，因涉及体力发放影响主盘消耗循环）
- 核心流程：
  1. 活动按服务器配置时间开启，玩家满足主线条件后可见入口
  2. 玩家点击入口进入活动界面，查看转盘上5档体力奖励
  3. 点击购买按钮 → 走通用支付流程 → 支付成功
  4. 跑马灯动画 → 揭示中奖奖励（不放回） → 弹出发奖弹板
  5. 点击领取 → 体力飞到体力槽 + 卡包飞到储物篮
  6. 界面刷新：已领取标记、价格递增、新卡包显示
  7. 重复购买直至5档全部领完 → 活动自动结束
  8. 或活动倒计时到期 → 活动结束，资源关闭
- 关键规则：
  - 不放回抽取：已获得的奖励从池中移除，不可重复获得
  - 批次+权重选取：按配置顺序分批次，同批次内按权重随机
  - 递增价格：每次购买后价格提升（走配置）
  - 赠送卡包：每次购买赠送0~2个卡包（走配置）
  - 1轮限制：活动期间只能购买1轮（共5次）
  - WHAT玩家分层
- 状态变化：
  - 活动状态：未开启 → 进行中 → 已结束
  - 购买进度：0/5 → 1/5 → ... → 5/5
  - 每档奖励状态：可获得 → 已获得（对勾标记）
  - 价格状态：逐次递增
  - 卡包赠品：逐次变化
- 资源变化：
  - 消耗：真实货币（$2.99 → 递增）
  - 产出：体力（420/600/1000/1400/2000 等配置值）+ 卡包（0~2个）
- 限制条件：
  - 主线任务完成才可见
  - 服务器配置的活动时间窗口
  - 1轮5次购买上限
  - WHAT分层控制可见性

## 2. 归属专项判断

- **主专项：活动 + 热更 + 弱网专项**
  - 这是一个有明确生命周期的付费活动（开启→运行→结束）
  - 涉及真金白银支付、补单逻辑、活动结束边界
  - 弱网/杀端恢复是核心风险场景
- **次级受影响专项：订单-奖励-剧情闭环专项**
  - 体力是主盘核心驱动资源，大量体力注入会影响主盘消耗循环节奏
  - 卡包飞到储物篮涉及主盘物品系统
- **判断理由：** Energy Rush 本质是一个"付费+不放回抽奖+体力发放"活动，核心风险集中在支付链路、奖励发放唯一性、活动生命周期边界和弱网补单，完全对应活动+热更+弱网专项。但因为产出体力和卡包直接注入主线资源池，次级需关注对主盘循环的影响。

---

## 3. 影响范围

- 涉及模块：活动系统、支付系统、体力系统、卡包/储物篮系统、弹窗系统、倒计时系统
- 依赖系统：通用支付流程（IAP/第三方支付）、服务器活动配置、WHAT分层服务、体力槽/体力上限、储物篮/背包、邮件系统（补发兜底）
- 可能受影响的旧功能：
  - 体力系统：大量体力注入后体力上限/溢出/恢复逻辑
  - 储物篮/背包：卡包落点，储物篮满时处理
  - 其他付费活动：同时存在多个付费活动时支付回调路由
  - 弹窗优先级系统：登录弹窗、体力不足弹窗与其他活动/剧情弹窗冲突
  - 通用补单逻辑：补单与本活动的奖励确定性结果绑定
- 联动关注点：
  - 体力注入后主盘生产器使用频率变化，是否影响主线节奏
  - 卡包进入储物篮后的开包流程是否正常
  - 支付回调与其他付费入口（商店、其他活动礼包）的路由隔离
  - 活动结束时刻与跨日刷新同时发生的处理
  - WHAT分层配置下发失败时的兜底（能不能看到活动）

## 4. 风险分析

| 风险名称 | 风险等级 | 触发条件 | 影响范围 | 推荐测试方向 |
|---|---|---|---|---|
| 支付成功但奖励未发放 | P0 | 支付回调成功，但服务端未正确记录奖励结果或客户端未弹发奖弹板 | 玩家资产、付费信任 | 支付全流程验证 + 各阶段中断恢复 |
| 支付回调重复导致重复发奖 | P0 | 网络超时/重试导致支付回调被执行多次，同一次购买发放了多份体力或卡包 | 资源刷取、经济系统 | 弱网+支付回调幂等性验证 |
| 不放回抽取失效——同一奖励重复获得 | P0 | 并发/弱网/补单导致已获得奖励未从池中正确移除，再次购买时重复命中 | 奖励正确性、不放回机制 | 连续购买 + 弱网购买 + 杀端补单后继续购买 |
| 补单逻辑与奖励确定性不一致 | P0 | 支付成功杀端后，补单时发放的奖励与服务端已确定的结果不一致 | 玩家资产、数据一致性 | 支付中各Step杀端 → 重登 → 验证补单结果 |
| 活动结束瞬间完成支付——付了钱但没发奖 | P0 | 付费流程中活动倒计时到期，回调时活动已关闭，奖励被拒 | 玩家资产、付费纠纷 | 活动即将结束时发起支付 → 验证补单逻辑 |
| 购买次数突破5次上限 | P0 | 弱网/并发/客户端缓存导致第6次购买被执行 | 经济系统、不放回机制崩溃 | 第5次购买弱网 + 连点 + 重登后状态验证 |
| 体力发放但未到账体力槽 | P1 | 飞奖动画中闪退/切后台，体力飞行未完成但服务端已发放 | 玩家体验、资产感知 | Step4飞奖阶段中断恢复 |
| 卡包发放但储物篮满 | P1 | 储物篮已满时购买，卡包无处落地 | 玩家资产、卡包丢失 | 储物篮满/临界时购买，验证兜底路径 |
| 批次权重选取逻辑错误 | P1 | 配置N个批次+权重后，实际选取不符合批次顺序或权重分布 | 奖励正确性、数值策略 | 多次购买验证批次顺序 + 同批次权重分布 |
| 价格递增配置错误 | P1 | 购买后价格未按配置递增，或递增后显示与实际扣款不一致 | 付费金额、合规风险 | 逐次购买验证显示价格与实际扣款一致性 |
| info面板概率显示与实际不符 | P1 | info展示的概率与实际配置的批次权重不一致，或已获得状态未正确标记 | 合规风险、玩家信任 | 每次购买后验证info面板更新 |
| 弹窗优先级冲突导致活动入口被吞 | P2 | 登录时多个弹窗竞争，活动弹窗被覆盖或跳过 | 活动曝光、商业化效果 | 多弹窗并存场景下验证优先级 |
| 跨日后活动状态异常 | P2 | 跨日时购买进度/价格/倒计时刷新异常 | 活动状态 | 跨日前后验证活动状态一致性 |
| WHAT分层配置下发失败 | P2 | 分层服务异常，应看到活动的玩家看不到，或不应看到的看到了 | 活动资格 | 分层正常/异常/超时场景验证 |

## 8. 本次最危险的问题

1. **支付成功但奖励未发放（钱扣了但啥都没给）** — 真金白银付费活动的致命问题，支付各阶段中断（杀端、断网、切后台）+ 补单逻辑是最高优先级测试目标
2. **支付回调重复导致重复发奖（一次购买发多次体力）** — 弱网+超时重试+补单并发是经典的重复发奖漏洞，直接刷资源
3. **不放回机制失效（同一奖励被重复获得）** — 整个活动的核心数学模型依赖不放回，一旦穿透则奖励分配完全错误
4. **活动结束边界时刻付费纠纷** — 付费流程中活动结束是现实中最容易引发玩家投诉的场景，补单逻辑必须覆盖
5. **第5次购买边界——突破上限或丢失最后一次奖励** — 最后一次购买涉及"发奖+活动关闭"两个动作同时发生，叠加弱网/杀端最容易出问题
