# 测试分析输出：Energy Rush——充能狂潮活动

---

## 1. 需求摘要

- 功能名称：Energy Rush（充能狂潮）——付费体力售卖活动
- 功能目标：以不放回抽取 + 递增价格的付费模型，售卖体力并搭配卡包赠品，刺激玩家付费
- 玩家入口：
  - 主界面右侧活动入口列表（排序走配置）
  - 登录弹窗（优先级走配置）
  - 体力不足时弹窗（可配置是否弹）
- 归属专项：**活动 + 热更 + 弱网专项**（主）；订单-奖励-剧情闭环专项（次级）
- 核心流程：
  1. 活动按服务器配置时间开启
  2. 满足通用条件 ID=2（完成主线任务）的玩家可见入口
  3. 玩家进入活动界面，查看转盘上 5 档体力奖励和 info 概率面板
  4. 点击购买按钮 → 走通用支付流程
  5. 支付成功 → Step1 跑马灯（所有可选奖励均须被摇到） → Step2 揭奖停留 → Step3 弹出发奖弹板（Rush Hit!） → 点击任意位置领取
  6. Step4 体力飞到体力槽 + 卡包飞到储物篮 → Step5 界面刷新（已领取标记、价格递增、新卡包显示）
  7. 重复购买直至 5/5 全部领完 → 活动自动结束；或活动倒计时归零 → 活动结束
- 关键规则：
  - **不放回抽取**：已获得奖励从池中移除
  - **批次 + 权重选取**：按配置的奖励获取顺序分批次，同批次内按权重随机
  - **递增价格**：每次购买后价格提升（走配置）
  - **卡包赠品**：每次购买赠送 0~2 个卡包（走配置）
  - **1 轮限制**：活动期间只能购买 1 轮（共 5 次）
  - **WHAT 玩家分层**：不同分层看到不同活动配置
  - **倒计时**：走通用倒计时规则（>1天显示X天X时 / >1小时显示X时X分 / >1分钟显示X分X秒 / ≤1分钟显示X秒）
  - **卡包显示**：走卡包奖励通用显示规则（右上角 i 按钮、气泡显示星级和卡片数量）
  - **补单逻辑**：走通用补单，支付成功杀端后回到游戏弹出发奖弹板补发确定的奖励结果
- 状态变化：
  - 活动状态：未开启 → 进行中 → 已结束（倒计时归零或 5/5 购完）
  - 购买进度：0/5 → 1/5 → ... → 5/5
  - 每档奖励状态：可获得 → 已获得（对勾标记）
  - 价格状态：按配置逐次递增
  - 支付按钮状态：可点击 → 置灰（支付/动画中） → 可点击
- 资源变化：
  - 消耗：真实货币（$2.99 起，逐次递增）
  - 产出：体力（420/600/1000/1400/2000 等配置值）+ 卡包（0~2 个）
- 限制条件：
  - 通用条件 ID=2（完成指定主线任务）
  - 服务器配置的活动时间窗口
  - 1 轮 5 次购买上限
  - WHAT 分层控制可见性和配置内容

## 2. 归属专项判断

- **主专项：活动 + 热更 + 弱网专项**
  - 这是一个有明确生命周期的运营付费活动（未开启 → 进行中 → 已结束）
  - 涉及真金白银支付 + 通用补单逻辑
  - 弱网/杀端/活动结束边界是核心风险场景
- **次级受影响专项：订单-奖励-剧情闭环专项**
  - 体力是主盘核心驱动资源，大量体力注入直接影响盘面消耗循环
  - 卡包飞到储物篮涉及主线物品系统（卡包通用显示规则、储物篮容量）
- **不涉及：盘面与物品链专项**
  - 本活动不操作盘面、不涉及物品链合成、不使用活动盘
- **判断理由：** Energy Rush 本质是"付费 + 不放回抽奖 + 体力/卡包发放"的独立弹窗活动，无独立活动盘，核心风险集中在支付链路安全、奖励发放唯一性、活动生命周期边界和弱网补单，完全对应活动 + 热更 + 弱网专项。因产出体力和卡包直接注入主线资源池，次级关注对主盘循环和储物篮的影响。

## 3. 影响范围

- 涉及模块：活动系统、通用支付流程、通用补单逻辑、体力系统、卡包/储物篮系统、弹窗优先级系统、倒计时系统、WHAT 分层服务
- 依赖系统：IAP/第三方支付回调、服务器活动配置下发、通用条件判断（ID=2 主线任务完成）、通用倒计时组件、卡包奖励通用显示组件
- 可能受影响的旧功能：
  - **通用支付流程**：新增一个支付消费者（Energy Rush），支付回调路由需正确分发
  - **通用补单逻辑**：补单需绑定活动特有的"已确定奖励结果"，不可与其他付费商品补单串线
  - **体力系统**：大量体力注入后的上限/溢出/恢复计时逻辑
  - **储物篮**：卡包落点，储物篮满时兜底处理
  - **弹窗优先级**：登录弹窗和体力不足弹窗新增触发源，可能与其他活动/剧情/引导弹窗冲突
  - **活动入口列表**：新增一个入口，需正确排序和生命周期管理
- 联动关注点：
  - 体力注入后主盘生产器使用频率变化，不应打破主线节奏
  - 卡包进储物篮后开包流程（走卡包通用显示和开包规则）
  - 支付回调与其他付费入口（商城体力、其他礼包活动）的隔离
  - 活动结束时刻与跨日刷新同时发生时的状态处理
  - WHAT 分层配置下发失败时的兜底（不应让不该看到的玩家看到，也不应让该看到的玩家看不到）

## 8. 本次最危险的问题

1. **支付成功但奖励未发放（扣钱没发货）** — 涉及真金白银的 P0 事故。支付各阶段中断（杀端、断网、切后台）+ 通用补单逻辑是测试最高优先级。**历史问题 7 直接命中。**
2. **支付回调重复导致重复发奖（一次购买多发体力/卡包）** — 弱网+超时重试+补单并发是经典重复发奖漏洞，直接刷资源。**历史问题 7 直接命中。**
3. **不放回机制失效（同一奖励被重复获得）** — 整个活动的核心数学模型依赖不放回。弱网/补单/并发下如果已获得奖励未正确从池中移除，活动机制彻底崩溃。
4. **活动结束边界时刻付费纠纷** — 策划案已设计此场景但实现易出错。"付了钱活动关了没给东西"是线上投诉高发场景。**历史问题 8 直接命中。**
5. **第 5 次购买边界（发奖+活动关闭同时发生）** — 最后一次购买涉及"发奖 + 关闭活动"两个动作叠加。加上弱网/杀端，最容易出现购买次数突破上限或最后一次奖励丢失。

盯住支付回调、领取、连续购买、第 5 次边界。

**第 5 步：联动回归（TC-029, TC-036~TC-039）**
确认不打坏通用支付、通用补单、体力系统、储物篮。

**第 6 步：弹窗/入口/分层/显示（TC-026~TC-028, TC-030~TC-033）**

### 必须验证的恢复路径
```
支付成功杀端（回调前）   → 重登 → 通用补单 → 发奖弹板 → 奖励唯一正确
支付成功杀端（跑马灯中） → 重登 → 通用补单 → 跳过动画直接发奖
支付成功杀端（发奖弹板中）→ 重登 → 重新弹板 → 不重复发奖
支付成功杀端（飞奖中）   → 重登 → 奖励已到账 → 界面状态正确
活动结束时支付完成        → 回到游戏 → 正常发奖 → 活动关闭
```

### 必须验证的幂等节点
```
支付回调：只执行 1 次发奖，重试不重发
补单逻辑：与原单互斥不并发，结果=服务端确定结果
领取操作：多次点击只发 1 次
购买次数：严格 ≤5 次，弱网/杀端不可突破
不放回池：已获得奖励永久从池中移除，不可恢复
```
