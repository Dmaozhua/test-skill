# 真实试跑输出

## 1. 需求摘要

- **功能名称**：限时活动阶段奖励领取与活动结束边界处理
- **功能目标**：在限时活动中，玩家达成阶段积分阈值后可领取一次性阶段奖励；活动结束后，对已达成未领取奖励做邮件补发，并正确关闭活动入口、冻结活动盘、切换活动状态。
- **玩家入口**：主界面活动 Banner、活动浮层入口、活动盘阶段奖励面板。
- **核心流程**：进入活动 → 获取活动积分 → 达到阶段阈值 → 领取阶段奖励 → 状态更新 → 活动结束 → 邮件补发未领取奖励 → 活动关闭与清理。
- **关键规则**：
  - 阶段奖励只可领取一次
  - 未达成阈值不可领取
  - 活动结束后不可再手动领取
  - 已达成未领取奖励需邮件补发
  - 活动盘、主盘、奖励落点必须隔离
  - 弱网 / 重登后奖励状态必须唯一正确
- **状态变化**：
  - 阶段状态：未达成 → 可领取 → 已领取
  - 活动状态：未开启 → 已开启 → 进行中 → 即将结束 → 已结束待结算 → 已清理
  - 奖励状态：未发放 → 已发放 / 已邮件补发
- **资源变化**：活动积分增加；阶段奖励到账；活动结束后邮件奖励到账。
- **限制条件**：受活动配置与时间控制；活动结束前后边界时刻为高风险节点。

---

## 2. 影响范围

- **涉及模块**：活动入口、活动盘、活动任务/订单、阶段奖励面板、奖励发放、邮件系统、活动状态机、活动清理逻辑、红点/弹窗。
- **依赖系统**：
  - 活动配置与时间控制
  - 奖励发放与邮件兜底
  - 主盘/活动盘隔离逻辑
  - 弱网重试与状态恢复
- **可能受影响的旧功能**：
  - 其他活动奖励面板
  - 邮件补发链路
  - 主盘奖励发放落点
  - 排行榜 / 阶段奖励共用结算逻辑
  - 活动结束后的主界面入口清理
- **联动关注点**：
  - 活动积分是否正确驱动阶段状态
  - 领奖成功后是否正确更新阶段状态与红点
  - 活动结束时未领奖励是否仅通过邮件补发一次
  - 活动关闭后活动盘是否不可再产生有效进度

## 4. 测试点矩阵

| 维度 | 测试点 |
|---|---|
| 主流程 | 达到阶段阈值后正常领取奖励；领奖后状态变已领取；活动结束后入口关闭、未领奖励邮件补发 |
| 分支流程 | 多阶段连续达成；部分阶段已领、部分未领；不同资格玩家活动状态差异 |

## 6. 回归建议

### 必回归
- **邮件补发链路**
  - 原因：本需求直接依赖活动结束后的邮件兜底发奖
  - 重点验证：补发邮件下发、领取、重复登录后不重复补发、邮件领取后状态一致

- **其他活动阶段奖励面板 / 共用领奖组件**
  - 原因：共用“达成→可领取→已领取”状态机与领奖逻辑
  - 重点验证：正常领奖、连点、弱网、状态刷新、红点状态

- **活动结束清理逻辑**
  - 原因：本需求直接覆盖活动关闭、入口移除、活动盘冻结与清理
  - 重点验证：结束后入口、盘面、奖励、邮件、清理状态

### 建议回归
- **主盘/活动盘奖励落点规则**
  - 原因：本需求要求活动奖励与主盘隔离，容易串数据
  - 重点验证：活动奖励归属、主盘奖励不受污染、特殊物品落点正确

- **活动排行榜 / 阶段奖励共用结算逻辑**
  - 原因：可能共用活动结束、结算、补发逻辑
  - 重点验证：锁榜、结算、结算邮件、活动结束边界状态

- **活动 Banner / 红点 / 弹窗优先级**
  - 原因：活动关闭与入口露出强相关
  - 重点验证：结束后主界面状态刷新、残留入口、红点同步

### 抽查回归
- **主线邮件奖励与订单奖励链路**
  - 原因：与本次活动邮件补发属于弱耦合，但共享部分奖励发放规则
  - 重点验证：一般邮件领取、订单奖励到账、奖励状态更新

- **热更后活动恢复**
  - 原因：本轮需求未直接改热更，但活动结束边界与配置更新有耦合风险
  - 重点验证：活动结束前后配置切换、重登恢复、老状态兼容

## 7. 本次最危险问题提醒

1. **活动结束前最后 1 秒领奖，既即时到账又邮件补发，导致双发。**
2. **弱网下领奖请求重复提交，阶段奖励被多次发放。**
3. **活动结束后停留在活动盘仍可继续产生积分或继续领奖。**
4. **已达成未领取奖励活动结束后既不允许手领，又未邮件补发，形成漏发。**
5. **活动奖励落点串到主盘或污染主线物品规则，形成长期脏数据。**
