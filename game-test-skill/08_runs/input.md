# 首次试跑输入包

## 1. 试跑目标
验证当前 test-skill 是否能基于真实项目资料，对一个 **高风险、强运营态、强边界时刻** 的需求，产出可执行的测试分析与测试用例。

本次选择需求：
**限时活动的阶段奖励领取 + 活动结束边界结算**

选择原因：
- 属于线上事故高发区
- 同时覆盖奖励发放、活动生命周期、时间边界、弱网幂等、主盘/活动盘隔离
- 最能检验 test-skill 是否真正吸收了真实项目知识

## 2. 本次模拟需求

### 2.1 功能名称
限时活动阶段奖励领取与活动结束边界处理

### 2.2 功能目标
在限时活动中，玩家通过完成活动任务累计活动积分；当积分达到阶段阈值时，可领取对应阶段奖励。活动结束后：
- 未领取但已达成的阶段奖励，需自动通过邮件补发
- 活动入口关闭
- 活动盘冻结并进入清理流程
- 活动状态切入“已结束待结算/已清理”

### 2.3 玩家入口
- 主界面活动 Banner
- 活动浮层入口
- 活动盘内阶段奖励面板

### 2.4 核心流程
1. 玩家进入活动
2. 完成活动订单/任务获得活动积分
3. 达到阶段阈值
4. 点击领取阶段奖励
5. 奖励正确到账并更新领取状态
6. 活动结束时，未领取但已达成奖励自动邮件补发
7. 活动入口关闭，活动盘不可继续产生有效进度

### 2.5 关键规则
- 阶段奖励只能领取一次
- 未达成阈值时不能领取
- 已领取奖励不能重复领取
- 活动结束后不可手动再领取阶段奖励
- 活动结束后，已达成未领取奖励必须通过邮件兜底
- 活动盘与主盘资源、物品、奖励落点必须隔离
- 弱网/断网/重登后，奖励领取状态必须唯一正确

### 2.6 状态变化
- 阶段状态：未达成 → 可领取 → 已领取
- 活动状态：未开启 → 已开启 → 进行中 → 即将结束 → 已结束待结算 → 已清理
- 奖励状态：未发放 → 已发放 / 已邮件补发

### 2.7 资源变化
- 活动积分增加
- 领取后发放活动阶段奖励
- 活动结束后可能发放邮件补发奖励

### 2.8 限制条件
- 活动时间受配置控制
- 阶段阈值来自活动配置
- 奖励落点遵循活动与主线隔离规则
- 活动结束前最后 1 秒、结束瞬间、结束后首次重登均属于高风险时刻
