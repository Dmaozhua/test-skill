# AGENTS.md

## 目标
本仓库用于生成**贴合当前项目**的测试分析与测试用例，不做通用泛化输出。

当前默认项目类型：**Merge+Story**
核心闭环：**盘面合成 → 订单交付 → 奖励回流 → 剧情/装修推进 → 活动运营**

---

## 默认读取顺序
处理任何需求时，默认按这个顺序理解资料：

1. `01_project_context/`：长期项目知识
2. `03_bug_memory/`：历史高危问题
3. `08_runs/.../requirement.md`：本次新增需求
4. `08_runs/.../input.md`：本次运行重点说明
5. `04_feature_specs/`：仅在涉及旧逻辑时按需读取
6. `07_output_templates/`：按模板输出

不要跳过长期知识直接只看需求。

---

## 目录语义
- `01_project_context/`：当前项目长期有效规则
- `03_bug_memory/`：高危老坑与事故模式
- `04_feature_specs/`：历史策划案 / 旧规则 / 旧配置说明
- `08_runs/`：本次真实任务运行记录

---

## 工作原则
1. **先风险，后用例**
2. **高危优先于完整**
3. **专项优先于页面**
4. **输出必须可执行**
5. **回归必须说明原因**
6. **旧逻辑才引用历史策划案**

---

## 必须优先防守的问题
- 卡死 / 锁死 / 无法恢复
- 资源刷取 / 重复收益
- 奖励多发 / 漏发 / 错发
- 付费异常 / 重复发货
- 状态错乱 / 数据污染
- 活动生命周期边界异常
- 热更兼容异常
- 弱网 / 断网 / 重连下幂等失效

---

## 默认输出顺序
1. 需求摘要
2. 影响范围
3. 风险分析
4. 测试点矩阵
5. 详细测试用例
6. 回归建议
7. 本次最危险问题提醒

---

## 回归规则
回归建议必须分层：
- 必回归
- 建议回归
- 抽查回归

每条都要写：
- 模块
- 原因
- 重点验证内容

不要无脑扩大回归范围。

---

## 运行规则
每个 `08_runs/.../` 目录默认至少包含：
- `requirement.md`
- `input.md`
- `output.md`
- `review.md`

其中：
- `requirement.md` = 本次需求原文或整理版
- `input.md` = 本次主专项、次专项、重点风险、补充资料
- `output.md` = AI 正式输出
- `review.md` = 人工复核与改进意见

---

## run 结束后
如果本次发现了新的高危模式，回写到：
- `03_bug_memory/`

如果本次暴露了长期规则变化，回写到：
- `01_project_context/`

---

## 默认风格
- 不空泛
- 不只写正常流程
- 不脱离项目背景
- 不忽略边界、异常、恢复、联动
- 优先输出 P0 / P1
