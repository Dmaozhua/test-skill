# AGENTS.md

## 1. 本仓库的目标

本仓库用于构建一个面向当前游戏项目的测试设计 skill，不是通用 prompt 仓库。

它的目标不是泛泛生成测试步骤，而是：

- 基于当前项目的长期知识、历史高危问题、历史策划案和本次新增需求
- 输出贴合当前项目的测试分析、测试点矩阵、详细测试用例和回归建议
- 优先防守高危问题，例如：
  - 卡死 / 锁死 / 无法恢复
  - 资源刷取 / 重复收益
  - 奖励多发 / 漏发 / 错发
  - 付费异常 / 订单异常 / 重复发货
  - 状态错乱 / 数据污染
  - 活动生命周期边界异常
  - 热更兼容异常
  - 弱网 / 断网 / 重连下幂等失效

---

## 2. 当前项目范围

当前仓库的项目范围默认是 **Merge+Story 类游戏**，测试设计的核心对象围绕以下闭环：

**盘面合成 → 订单交付 → 奖励回流 → 剧情 / 装修推进 → 活动运营循环**

当前专项重点分为三块：

1. 盘面与物品链专项
2. 订单-奖励-剧情闭环专项
3. 活动 + 热更 + 弱网专项

当需求进入时，应先判断它主要属于哪个专项，再进行风险识别和测试设计。

## 3. 目录语义

### `01_project_context/`
长期项目知识区。  
这里的内容默认优先级最高，优先于历史策划案和单次 run 输入。

### `03_bug_memory/`
历史高危问题区。  
这里不是普通 bug 列表，而是高价值老坑和高危模式记忆库。

### `04_feature_specs/`
历史策划案 / 旧功能规则 / 旧配置说明区。  
这里的内容不是默认常驻上下文，只在本次需求涉及旧逻辑时按需引用。

### `05_input_templates/`
输入模板区。  
用于整理项目资料和需求输入，但不是项目事实本身。

### `06_prompts/`
AI 固定规则区。  
用于约束角色、流程、输出顺序和风险识别方式。

### `07_output_templates/`
输出模板区。  
用于统一 AI 输出结构。

### `08_runs/`
本次真实任务运行区。  
每一个 run 都代表一次具体需求的测试设计过程。

---

## 4. 默认工作顺序

在处理任何新增需求时，默认按以下顺序工作：

1. 先读取 `01_project_context/`，建立项目长期认知
2. 再读取 `03_bug_memory/`，联想历史高危问题
3. 再读取本次 `08_runs/.../requirement.md`
4. 如果本次需求涉及旧逻辑，再按需读取 `04_feature_specs/` 相关文档
5. 最后按 `06_prompts/` 和 `07_output_templates/` 的规则输出结果

不要反过来先读需求再临时补规则。  
规则与长期知识优先，单次需求后置。

---

## 5. 输出要求

默认输出必须包含以下部分，顺序不得打乱：

1. 需求摘要
2. 影响范围
3. 风险分析
4. 测试点矩阵
5. 详细测试用例
6. 回归建议
7. 本次最危险问题提醒

如果当前需求风险很高，优先压实 P0 / P1。  
如果时间有限，优先保证高危路径，而不是追求面面俱到。

---

## 6. 测试设计总原则

### 原则 1：先风险，后用例
不允许直接跳过风险分析写测试步骤。

### 原则 2：高危优先
优先防守资源、奖励、付费、状态、恢复、活动边界、热更兼容、弱网幂等。

### 原则 3：专项优先于页面
不要只按页面看功能，要按闭环和专项看问题。

### 原则 4：可执行优先于漂亮
输出必须能直接给测试人员加工使用，避免空泛描述。

### 原则 5：回归必须有理由
不要无脑扩大回归范围。所有回归建议都要说明原因和重点验证内容。

---

## 7. 何时引用历史策划案

只有满足以下任一情况时，才引用 `04_feature_specs/`：

- 本次需求直接改到了旧逻辑
- 本次需求复用了旧规则 / 旧状态机 / 旧奖励链路
- 本次需求看似新增，实则套在旧功能壳上
- 该功能历史上出过类似高危问题

否则优先只依赖长期知识和本次需求。

---

## 8. 何时回写长期知识

完成一次 run 后，如果发现以下内容，应回写：

### 回写到 `03_bug_memory/`
- 新出现的高危模式
- 新出现的重复型老坑
- 新发现的高利用空间

### 回写到 `01_project_context/`
- 项目核心规则变化
- 测试策略重点变化
- 边界或回归口径变化

---

## 9. 默认判断风格

- 不要把普通问题写成严重事故
- 也不要放过高危利用路径
- 不要脱离项目背景泛泛输出
- 不要只写正常流程
- 不要忽略边界、异常、恢复和联动

---

## 10. 目标

本仓库希望形成可持续运转的闭环：

**长期知识维护 → 本次需求输入 → AI 输出测试分析 → 人工复核 → 新风险沉淀回知识库**
