# AGENTS.md

## 1. 本目录的作用

`03_bug_memory/` 是历史高危问题区。

这里记录的是项目中最值钱的老坑和高危模式，不是普通 bug 清单。

目标是让 AI 在处理新需求时，主动联想到：

- 过去哪些问题出现过
- 哪些问题最容易复发
- 哪些问题最容易漏测
- 哪些问题最可能形成线上事故或资源漏洞

---

## 2. 这里应该收什么

适合收录：

- 资源刷取问题
- 奖励重复发放 / 漏发 / 错发问题
- 付费异常 / 订单异常 / 补单异常
- 卡死 / 锁死 / 无法恢复问题
- 活动边界异常
- 热更兼容问题
- 弱网 / 断网 / 重连下的状态异常
- 客户端与服务端严重不一致问题
- 反复出现的联动事故

---

## 3. 这里不应该收什么

不适合收录：

- 普通文案问题
- 一般 UI 问题
- 一次性低影响缺陷
- 无复用价值的小问题
- 单次 run 的原始输出内容

---

## 4. 使用原则

### 原则 1：高危联想优先
只要本次需求涉及相似链路，就应主动联想本目录中的历史模式。

例如：
- 涉及领奖 → 联想重复领奖 / 漏发 / 补发并存
- 涉及活动结束 → 联想结束边界 / 清理残留 / 邮件补发
- 涉及热更 → 联想旧存档兼容 / 半更状态 / 状态断裂
- 涉及弱网 → 联想重复请求 / 状态分叉 / 假成功假失败

### 原则 2：优先看模式，不只看表面模块
本目录里的价值在于“问题模式”，不只是“某个页面出过 bug”。

### 原则 3：如果历史上该类问题出过坑，当前需求的风险等级应自动提高
即使本次策划案看起来简单，也不能轻易放过。

---

## 5. 在测试分析中的作用

处理本次需求时，读取本目录后，至少应回答：

- 本次需求是否踩中了历史相似风险模式
- 哪些历史问题会在这次需求里再次出现
- 本次测试是否应增加边界、恢复、幂等或回归覆盖
- 哪些高危问题不能只测正常流程

---

## 6. run 结束后何时回写这里

如果本次 run 中发现以下内容，应考虑回写：

- 新的高危利用路径
- 新的重复型老坑
- 新的活动边界事故模式
- 新的热更兼容风险模式
- 新的恢复性断裂模式
- 新的奖励 / 资源 / 状态幂等问题
