# 历史高危问题

## 1. 文档目标

本文件用于沉淀当前项目中最值钱的测试经验。

它不是普通 bug 清单，也不是缺陷导出表。  
这里只记录真正高价值的问题：

- 严重事故
- 容易复发的问题
- 容易漏测的问题
- 玩家可利用的问题
- 涉及资产、状态、付费、奖励的关键问题

未来 AI 是否真的“像懂项目的主测”，很大程度取决于这份文档。

---

## 2. 收录标准

以下问题建议收录：

### 2.1 必收问题
- 资源刷取问题
- 奖励重复发放问题
- 支付 / 订单 / 到账异常
- 卡死 / 锁死 / 无法恢复
- 跨天 / 刷新 / 限次异常
- 多端 / 断线 / 重连导致状态异常
- 客户端与服务端状态严重不一致

### 2.2 可选收录问题
- 影响范围很大的联动问题
- 反复出现的老问题
- 曾在线上造成明显影响的问题
- 曾经漏测过、代价较大的问题

### 2.3 不建议收录问题
- 普通 UI 显示问题
- 一般文案问题
- 低影响交互瑕疵
- 一次性且无复用价值的小问题

## 3. 记录模板

每条问题建议按下面格式记录。

---

### 问题标题
一句话描述问题本质。

### 问题类型
可选值示例：
- 资源刷取
- 奖励异常
- 付费异常
- 卡死
- 状态错乱
- 跨天异常
- 多端同步异常
- 联动回归问题
- 其他

### 影响模块
请明确写出涉及的系统，例如：
- 活动
- 商店
- 邮件
- 背包
- 支付
- 任务
- 排行榜
- 引导
- 登录
- 对局结算

### 触发条件
写清楚这个问题通常怎么触发。  
最好描述成可复测路径，而不是模糊总结。

### 实际后果
写清楚会造成什么影响：
- 玩家多拿资源
- 玩家资产丢失
- 玩家流程卡死
- 玩家状态异常
- 玩家支付后未发货
- 旧功能被带坏

### 根因简述（测试视角）
不要求深挖技术实现，但要说明测试上为什么容易漏：

- 缺少幂等保护
- 状态更新时机错误
- 回滚逻辑不完整
- 跨系统状态不同步
- 边界时间点未覆盖
- 弱网 / 重连未覆盖
- 共用链路改动未带回归

### 测试补防建议
以后遇到类似功能时，测试必须怎么补防。

建议写得具体，例如：
- 必须覆盖连点、弱网、重登
- 必须验证奖励状态与到账状态一致
- 必须验证补发和原发放不会并存
- 必须带相同资源链路回归

## 4. 推荐分类维护

为了后续更好复用，建议按类型逐步沉淀。

### 4.1 资源刷取类
重点记录：
- 连点重复领取
- 重复提交多次结算
- 断线重连双结算
- 多端切换双收益
- 限购未及时更新导致重复购买

### 4.2 奖励异常类
重点记录：
- 奖励未到账
- 奖励到账但状态未更新
- 奖励发错位置
- 背包满补发异常
- 邮件补发与原发放冲突

### 4.3 付费异常类
重点记录：
- 支付成功未到账
- 回调重复导致双发
- 订单状态异常
- 补单异常
- 首充 / 首购 / 月卡状态错误

### 4.4 卡死与状态锁死类
重点记录：
- 引导卡死
- 弹窗无出口
- 加载失败无恢复
- 操作后界面锁死
- 切后台返回无法继续

### 4.5 状态错乱类
重点记录：
- 客户端与服务端不同步
- 活动进度与奖励状态错乱
- 购买状态与库存状态错乱
- 任务状态与结算状态不同步

### 4.6 跨天 / 刷新 / 限次类
重点记录：
- 跨天双领奖
- 限购提前刷新 / 不刷新
- 活动结束后仍可进入 / 领奖
- 周期重置异常

## 5. 示例记录

以下示例仅用于占位，后续请替换成你们项目真实问题。

---

### 问题标题
活动阶段奖励在弱网下可重复领取

### 问题类型
资源刷取

### 影响模块
活动、奖励发放、背包

### 触发条件
玩家点击领奖时网络延迟，客户端连续发出多次领奖请求，服务端状态更新晚于奖励发放。

### 实际后果
同一档阶段奖励可到账两次及以上，导致玩家异常增加资源。

### 根因简述（测试视角）
领奖功能只验证了正常流程，没有覆盖弱网 + 连点 + 状态更新延迟的组合场景。

### 测试补防建议
后续所有领奖功能必须覆盖：
- 快速连点
- 弱网
- 领奖后立即切后台
- 领奖后立即重登
- 奖励到账状态与领奖状态一致性验证

---

### 问题标题
支付回调重复触发导致礼包重复到账

### 问题类型
付费异常

### 影响模块
支付、订单、发货、邮件

### 触发条件
支付成功后，第三方支付平台重复回调，订单状态落库延迟，导致重复发货逻辑生效。

### 实际后果
玩家只支付一次，但礼包发放两次。

### 根因简述（测试视角）
支付测试只验证了正常支付成功路径，没有覆盖回调重放、补单重放和订单状态幂等校验相关场景。

### 测试补防建议
后续所有支付类功能必须覆盖：
- 回调重复
- 补单重复
- 到账后重新进页面验证状态
- 首充 / 限购 / 商品状态联动验证

---

### 问题标题
引导过程中切后台返回后角色进入锁死状态

### 问题类型
卡死

### 影响模块
引导、主界面、功能解锁

### 触发条件
玩家在引导关键步骤中切后台，再回到游戏时，引导状态未正确恢复。

### 实际后果
玩家停留在不可操作状态，核心入口无法点击，流程中断。

### 根因简述（测试视角）
引导测试只覆盖了完整顺走流程，未覆盖切后台、掉线、重登等中断恢复场景。

### 测试补防建议
后续所有引导、半强制流程必须覆盖：
- 切后台
- 弱网
- 掉线
- 重登
- 中断恢复

## 7. 维护要求

- 优先补高价值问题，不要追求全量
- 问题描述要偏“测试可复用”，不是单纯事故复盘
- 同类问题如果重复出现，可以继续归纳为模式
- 每次出现新的线上高危问题或漏测问题，都建议及时补进来

## 8. 当前结论

本文件的目标，不是记录“出过哪些 bug”，  
而是告诉 AI：

**这个项目过去真正摔过哪些坑，以后别再轻易漏掉。**
