# 历史高危问题（按当前真实项目归纳）

## 1. 文档目标

本文件不是普通 bug 列表，而是当前 Merge+Story 项目的**高价值事故模式库**。

它的作用是让 AI 在看到新需求时，不只是“写正常流程”，而是能主动联想到：
- 这个需求会不会打断盘面底盘
- 会不会造成无解单或闭环断裂
- 会不会让活动盘和主盘串数据
- 会不会在热更、弱网、跨日时爆出线上事故

以下问题并非来自单一缺陷单，而是根据当前真实项目测试专项沉淀出来的**必须优先防守的历史风险模式**。fileciteturn0file4turn0file8turn0file3

## 3. 高危问题模式库

### 问题 1：物品链断链导致主线订单不可达
- 问题类型：主线卡死 / 配置错误
- 影响模块：物品链、订单、生产器、主线推进
- 触发方式：订单池刷出目标物，但当前阶段未开放对应生产器、分支链或来源链断裂
- 实际后果：玩家无法完成订单，主线推进中断
- 根因简述（测试视角）：只测订单展示或提交，没有核对订单目标的合法来源与当前阶段可达性
- 测试补防建议：新增订单、订单池调整、物品链变更时，必须补做“订单目标-来源-阶段可达性”校验 fileciteturn0file8turn0file4

### 问题 2：满盘状态下奖励或容器产出被吞
- 问题类型：资源丢失 / 盘面边界问题
- 影响模块：盘面、奖励发放、容器、邮件兜底
- 触发方式：在接近满盘或满盘状态下开启箱子、领取奖励、交付订单或剧情下发奖励
- 实际后果：新物品未落盘、未进邮箱、未入背包，玩家资产丢失
- 根因简述（测试视角）：满盘只测“提示是否出现”，没测奖励落点规则与兜底路径
- 测试补防建议：所有会产出新物的路径都必须覆盖满盘、临界 1 格、满盘+恢复场景 fileciteturn0file4turn0file8

### 问题 3：订单完成后奖励到账，但闭环未继续推进
- 问题类型：闭环断裂 / 状态联动失败
- 影响模块：订单、奖励、剧情、装修、章节推进
- 触发方式：订单完成并领奖后，剧情条件未重新计算，或新订单 / 新章节未正确开放
- 实际后果：单点功能看似正常，但玩家推进不下去
- 根因简述（测试视角）：测试分别验证了订单、奖励、剧情，但没有按“订单完成 → 奖励到账 → 推进触发”整链验证
- 测试补防建议：所有主线新增内容都必须按闭环跑通，而不是只测单页功能 fileciteturn0file8

### 问题 4：剧情触发或装修推进状态错序
- 问题类型：状态错乱 / 主线推进异常
- 影响模块：剧情、装修、章节、星星/剧情点
- 触发方式：多节点同时满足、剧情跳过、装修多步连续推进、断线或切后台恢复
- 实际后果：剧情提前触发、漏触发、重复触发，或星星扣了但装修没变
- 根因简述（测试视角）：只测“剧情播没播”，没测逻辑状态、完成标记和后续解锁状态
- 测试补防建议：剧情与装修必须校验“触发条件 → 播放表现 → 完成标记 → 后续解锁”四段状态链 fileciteturn0file8

### 问题 5：活动盘与主盘串数据
- 问题类型：数据污染 / 线上高危事故
- 影响模块：活动盘、主盘、奖励落点、活动物品链、主线物品链
- 触发方式：活动期间进入活动盘、领取活动奖励、活动关闭清理、断网 / 重登 / 热更恢复
- 实际后果：活动物品进入主盘，主盘资源污染活动盘，活动结束后残留不可清理数据
- 根因简述（测试视角）：活动功能只测进入和领奖，没把隔离原则当 P0 来扫
- 测试补防建议：任何活动需求都必须先验证“物品隔离、资源隔离、订单隔离、奖励落点隔离、恢复状态隔离” fileciteturn0file3

### 问题 6：热更后旧存档映射错误
- 问题类型：热更兼容 / 存档损坏
- 影响模块：盘面、订单、物品链、活动、旧存档恢复
- 触发方式：配置热更、生效中断、运行中热更、老版本玩家升级到新配置
- 实际后果：盘面变空/变乱、订单消失、已领奖状态重置、活动打不开
- 根因简述（测试视角）：只测冷启动热更成功，没测“正在玩时热更”和“老存档升级”
- 测试补防建议：热更专项必须覆盖主盘中、活动盘中、领奖中、剧情中，以及跨版本旧存档兼容 fileciteturn0file3

### 问题 7：弱网下重复领奖或重复结算
- 问题类型：资源刷取 / 幂等性缺失
- 影响模块：订单领奖、活动领奖、邮件、结算、购买
- 触发方式：高延迟、超时重试、断网后重连、客户端多次提交请求
- 实际后果：奖励多发、物品多扣 / 少扣、状态分叉
- 根因简述（测试视角）：只测“报不报错”，没测“最终状态是否唯一正确”
- 测试补防建议：所有提交类、领奖类、结算类需求都必须覆盖弱网、超时、重试、重登恢复，且验证最终状态唯一性 fileciteturn0file3turn0file9

### 问题 8：活动结束边界时刻状态错乱
- 问题类型：时间边界事故
- 影响模块：活动入口、活动领奖、活动排行、活动清理、邮件补发
- 触发方式：活动结束前后 1 秒、锁榜时刻、结算时刻、活动结束瞬间断网或停留在活动盘
- 实际后果：入口残留、领奖权限错误、清理失败、结算多发或漏发
- 根因简述（测试视角）：只测活动进行中，没把活动生命周期完整拉通
- 测试补防建议：所有活动按“未开始 → 开启 → 进行中 → 即将结束 → 已结束待结算 → 已清理”完整生命周期测试 fileciteturn0file3

## 4. 使用要求

AI 每次接到以下需求时，必须先回看本文件：
- 新物品链 / 新生产器 / 新订单
- 奖励结构调整
- 星星 / 剧情点 / 装修推进改动
- 新活动 / 活动规则改动
- 热更配置改动
- 弱网 / 恢复 / 重登相关需求

---

## 5. 当前结论

对当前项目而言，最值钱的历史经验不是“哪里出过小 bug”，而是：

**盘面不能坏，闭环不能断，活动不能串，热更不能炸，弱网不能刷。**
