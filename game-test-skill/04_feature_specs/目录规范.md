# 04_feature_specs 使用规范

## 1. 这部分是干什么的

`04_feature_specs/` 用来存放**历史策划案、旧功能方案、旧版本改版说明、活动方案、旧配置说明**。

它的作用不是长期常驻给 AI 背诵，而是：

> 当本次新增需求涉及旧功能、旧链路、旧活动、旧规则时，作为“按需召回”的上下文资料。

简单说：

- `01_project_context/` 是长期知识
- `03_bug_memory/` 是历史老坑
- `04_feature_specs/` 是历史功能策划库
- `08_runs/` 是每次真实运行记录

这四层不要混。

---

## 2. 这里应该放什么

适合放进 `04_feature_specs/` 的内容包括：

### 2.1 历史策划案
- 旧功能 PRD
- 旧活动案
- 旧订单池方案
- 旧物品链设计
- 旧剧情推进方案

### 2.2 历史改版说明
- 某系统从旧逻辑改到新逻辑的说明
- 某版本数值调整说明
- 某活动奖励规则改版说明
- 某热更配置替换说明

### 2.3 历史配置解释文档
- 订单池配置说明
- 物品链配置说明
- 活动阶段奖励配置说明
- 排行榜结算规则说明
- 商店限购刷新说明

### 2.4 旧版本兼容资料
- 存档兼容说明
- 热更兼容说明
- 旧字段废弃说明
- 新旧逻辑切换说明

---

## 3. 这里不应该放什么

以下内容不要放进 `04_feature_specs/`：

### 3.1 不放长期项目规则
这些应放在 `01_project_context/`：
- 项目概览
- 测试策略
- 边界测试清单
- 回归范围规则
- 输出格式规范

### 3.2 不放历史 bug
这些应放在 `03_bug_memory/`：
- 线上事故
- 高危漏洞
- 老坑模式
- 易复发问题

### 3.3 不放本次运行结果
这些应放在 `08_runs/`：
- requirement.md
- input.md
- output.md
- review.md

---
