# 测试策略

## 1. 文档目的

本文件用于告诉 AI：

- 当前项目测试最重视什么
- 什么问题属于高优先级
- 什么问题属于严重事故
- 生成测试内容时，应该优先防什么

如果没有这份文档，AI 很容易“平均发力”，最后写出一堆有用但不值钱的测试点。

---

## 2. 测试总原则

本项目测试不只是验证“功能能不能跑通”，更优先避免以下后果：

1. 玩家卡死、锁死、流程无法继续
2. 资源异常增减，尤其是可刷资源
3. 奖励重复发放或错误发放
4. 充值、订单、到账、发货异常
5. 状态错乱，导致进度、次数、奖励异常
6. 客户端显示正常，但服务端数据错误
7. 新功能带坏旧功能或旧链路

因此，本项目测试设计遵循以下原则：

- 高危优先于完整
- 数据正确优先于展示正确
- 可利用漏洞优先于普通异常
- 联动问题优先于孤立问题
- 新功能测试必须自带回归意识

---

## 3. 优先级定义

### 3.1 P0：严重事故级
满足任一情况，可判为 P0：

- 玩家卡死 / 锁死 / 无法退出
- 主流程阻塞，无法继续核心游戏流程
- 可重复刷资源
- 奖励重复发放
- 支付成功未到账
- 单次支付多次发货
- 数据严重污染且不可自行恢复
- 客户端与服务端严重不一致，影响玩家资产或核心状态

### 3.2 P1：高影响问题
满足任一情况，可判为 P1：

- 核心流程异常，但存在绕过方式
- 奖励状态异常，但不可重复刷取
- 活动 / 任务 / 商店 / 限购 / 次数 / 排行等核心系统异常
- 断线重连导致状态异常
- 高影响联动问题
- 资源扣了但收益未到账，或到账了但状态未及时更新

### 3.3 P2：一般功能问题
满足任一情况，可判为 P2：

- 分支流程异常
- 边界条件异常
- 低频场景表现不一致
- 次要状态不同步
- 对体验有影响，但不影响核心资产与主流程

### 3.4 P3：低影响问题
满足任一情况，可判为 P3：

- 文案问题
- 一般 UI 展示问题
- 不影响逻辑的数据展示偏差
- 低优先级提示交互问题

---

## 4. 必测维度

任何新增功能，原则上都必须先从以下维度判断是否需要覆盖：

- 主流程
- 分支流程
- 异常流程
- 边界条件
- 状态切换
- 重复点击 / 重复请求 / 并发
- 弱网 / 断网 / 高延迟
- 切后台 / 杀进程 / 重登 / 重连
- 跨天 / 刷新 / 倒计时边界
- 系统联动
- 回归影响

并不是每个功能都要求同等深度覆盖，但 AI 必须先主动检查这些维度。

---

## 5. 高危关注点

### 5.1 卡死 / 锁死 / 无法恢复
重点关注：
- 弹窗无出口
- 引导中断无恢复路径
- 加载失败后界面停住
- 返回后状态错误导致无法继续
- 某步骤失败后界面不可点且不刷新

### 5.2 资源刷取 / 重复收益
重点关注：
- 连点重复领奖
- 弱网下重复提交
- 断线重连重复结算
- 邮件重复领取
- 限购状态未更新
- 补发与原奖励并存
- 多端切换带来双重收益

### 5.3 奖励发放异常
重点关注：
- 奖励未到账
- 奖励到账但状态未更新
- 奖励发到错误位置
- 背包满时处理异常
- 邮件补发异常
- 部分奖励到账、部分失败

### 5.4 付费问题
重点关注：
- 支付成功未到账
- 支付回调重试导致重复发货
- 订单状态异常
- 首充 / 首购状态异常
- 月卡 / 基金 / 礼包状态异常
- 取消支付 / 超时支付状态异常

### 5.5 数据污染 / 状态错乱
重点关注：
- 状态未回滚
- 活动结束后残留旧状态
- 客户端与服务端不一致
- 多端登录导致状态错乱
- 配置切换后旧状态污染新逻辑
- 刷新前后状态切换错误

---

## 6. 风险识别规则

AI 在分析需求时，必须优先判断以下问题：

1. 是否涉及资源变化
2. 是否涉及奖励发放
3. 是否涉及付费 / 订单 / 商品购买
4. 是否涉及状态切换
5. 是否涉及限次 / 限购 / 刷新 / 跨天
6. 是否涉及背包 / 邮件 / 补发
7. 是否涉及弱网 / 断线 / 重连 / 多端
8. 是否涉及公共组件 / 公共逻辑 / 共用链路
9. 是否可能影响旧功能
10. 是否存在被玩家利用的空间

如果其中任意一项答案是“是”或“有可能”，就必须增强该方向测试。

---

## 7. 测试设计偏向

当时间有限时，优先覆盖顺序建议如下：

1. 主流程 + 资源 / 奖励 / 付费 / 状态正确性
2. 重复点击 / 并发 / 弱网 / 重连
3. 跨天 / 刷新 / 限次 / 边界时间点
4. 联动系统与高风险旧链路
5. 一般分支流程
6. 展示与文案细节

这部分很重要，它决定 AI 在资料不足或时间有限时，不会把力气花错地方。

---

## 8. 人工复核原则

AI 生成结果后，人工应重点复核：

- 是否理解错业务规则
- 是否忽略项目特有老坑
- 是否错误放大低风险问题
- 是否漏掉版本特殊配置
- 是否回归范围过大或过小
- 是否遗漏高危利用路径

AI 可以提高效率，但不能替代项目经验判断。

## 10. 当前结论

AI 后续输出测试分析和测试用例时，应始终优先守住：

- 卡死
- 资源
- 奖励
- 付费
- 状态
- 联动
- 回归
