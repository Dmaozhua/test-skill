# AGENTS.md

## 1. 本目录的作用

`01_project_context/` 是项目长期知识区。

这里存放的内容不是单次需求资料，而是当前项目长期成立、相对稳定的测试背景与规则，例如：

- 项目概览
- 测试策略
- 测试用例输出格式规范
- 边界测试清单
- 回归范围规则

处理任何新增需求时，应优先读取本目录内容，用于建立项目级理解。

---

## 2. 这里的内容优先级

本目录内容优先级高于：

- `04_feature_specs/` 中的历史策划案
- `08_runs/` 中的单次需求输入

当历史策划案与本目录长期规则冲突时，优先以本目录描述的当前项目口径为准，除非本次需求明确说明是旧逻辑沿用或旧版本兼容验证。

---

## 3. 读取方式

处理任何需求时，建议优先读取：

1. `项目概览.md`
2. `测试策略.md`
3. `边界测试清单.md`
4. `回归范围规则.md`
5. `测试用例输出格式规范.md`

目的不是背文档，而是建立以下判断基础：

- 这个项目的核心闭环是什么
- 当前项目最重视什么问题
- 这次需求该怎么看边界
- 这次需求该如何控制回归范围
- 输出结构应如何统一

---

## 4. 使用原则

### 原则 1：把这里当成当前项目的默认口径
默认认为这里记录的是“当前有效的项目测试认知”。

### 原则 2：不要把单次需求写进这里
单次需求放到 `08_runs/`，不要污染长期知识。

### 原则 3：不要把老旧策划案直接并入这里
历史设计属于 `04_feature_specs/`，只有当其已经成为项目当前默认规则时，才应提炼后写回这里。

### 原则 4：优先提炼，不要堆细节
这里适合写项目全局认知，不适合塞过多具体页面级实现细节。

---

## 5. 本目录输出给 AI 的核心作用

当 AI 读取本目录时，应得到以下稳定认知：

- 当前项目是什么类型的游戏
- 核心循环是什么
- 哪些系统是高风险系统
- 当前项目如何定义 P0 / P1 / P2 / P3
- 任何新增需求都必须优先检查哪些边界
- 回归范围应该如何分层和控制
- 输出测试结果时必须遵循什么结构

---

## 6. 适合写回这里的内容

如果 run 结束后发现以下变化，应考虑写回本目录：

- 项目核心循环变化
- 测试优先级定义变化
- 边界检查口径变化
- 回归判断口径变化
- 输出模板标准变化
- 当前版本长期风险重点变化

---

## 7. 不适合写回这里的内容

以下内容不要写进本目录：

- 单次需求原文
- 单次测试结果
- 一次性事故复盘细节
- 零散旧版本设计说明
- 普通 bug 列表
