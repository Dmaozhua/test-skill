# 测试用例输出格式规范

## 1. 目标

统一 AI 输出结构，保证：

- 每次输出格式一致
- 可直接给测试人员使用
- 后续能接表格、测试平台、知识库

---

## 2. 固定输出顺序

AI 输出必须按以下顺序：

1. 需求摘要
2. 影响范围
3. 风险分析
4. 测试点矩阵
5. 详细测试用例
6. 回归建议
7. 最危险问题提醒

---

## 3. 详细测试用例字段

每条测试用例至少包含：

- 用例 ID
- 用例标题
- 所属模块
- 优先级
- 风险标签
- 前置条件
- 操作步骤
- 预期结果

可选字段：
- 测试数据
- 关联需求
- 关联风险点
- 是否建议自动化
- 回归属性
- 备注

---

## 4. 用例标题规范

推荐格式：

`[模块] + [场景] + [期望结果]`

示例：
- [活动领奖] 正常领取阶段奖励，奖励正确到账且状态变为已领取
- [礼包购买] 弱网下重复点击购买，仅生成一笔有效订单并发货一次
- [新手引导] 第三步切后台后返回，可恢复引导且不会锁死界面

---

## 5. 风险标签建议

- main_flow
- exception
- boundary
- freeze
- exploit
- reward
- payment
- economy
- state_sync
- reconnect
- cross_day
- regression
- multi_device
- config_related

---

## 6. 步骤编写要求

- 一步一动作
- 特殊条件必须写清
- 涉及数据时必须写明数据预期
- 异常场景必须写清触发方式
